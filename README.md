# Калькулятор отбора проб воды

**Предварительный рейтинг / методика частично согласована.** Приложение подготавливает
отдельный рейтинг каждого месторождения для действующего эксплуатационного фонда:
дающих газ и остановленных в отчётном периоде. Неизвестные вклады показываются
отдельно; сумма подтверждённых вкладов рассчитывается без перенормировки весов.

Интерфейс сохраняет сценарий принятого ГДИС: источники → «Проверить файлы» →
месторождение → «Критерии…» → «Обновить калькулятор», прогресс и журнал.
История запусков, ЗБС и переводов берётся из «Базы по скважинам». Мониторинг
штуцеров необязателен. План ГТМ и координаты больше не требуются и не читаются.

Для разработки нужны Python 3.14 и uv:

```bash
uv sync --locked
uv run water-sample-ranker validate --as-of 2042-11-05
uv run water-sample-ranker update --field береговое --output outputs/new.xlsx
uv run water-sample-ranker update-all --output-dir outputs/new-batch
uv run water-sample-ranker-gui
```

Windows-приложение поставляется отдельно как `onedir`: распакуйте ZIP целиком,
сохраняя `_internal`, `templates` и уведомления библиотек. Python на рабочем
месте не требуется. Версия и SHA исходного кода доступны в «О программе».

В Excel сохранены шесть листов: `README`, `Настройки`, `Данные`, `Критерии`,
`Расчет`, `Рейтинг`. Голубые ячейки `Настройки!D21:D28` — веса,
`I21:I28` — включение критериев, `B7` — фиксированная дата расчёта.
В ручной таблице ниже строки 55 выберите «Отбор пробы после ГТМ»:
«Да», «Нет» или «Не задано». Формулы изменяют сумму и место без загрузчика.
Там же можно явно подтвердить увеличение фактического диаметра штуцера:
дата, два диаметра в мм и основание. Проценты открытия не подходят.

Для сохранения отметок при обновлении выберите предыдущую книгу как калькулятор
или укажите её в поле «Предыдущая книга (ручные отметки)» / `--manual-input`.
Для повторного пакетного выпуска этот параметр принимает каталог предыдущих
книг: ровно одна книга на месторождение. Сохраняются архивные стадии; перенос
отметки на новую стадию запрещён. Дубликаты и конфликты блокируют публикацию.
Новый результат получает новое имя; исходные книги не перезаписываются.

№1 использует настраиваемый предварительный режим полных календарных месяцев
с ограничением дня последним днём короткого месяца и насыщением после года.
№6 реализует входное условие: FAIL даёт ноль, PASS — `PENDING_CUSTOMER_RULE`
без бонуса, пока не согласован второй шаг. №9 отложен заказчиком.
Равный балл означает ничью; нумерация competition — технический черновой выбор.
Дата в Excel пересчитывает давность, но не меняет зафиксированный снимок источников;
для другого исторического снимка нужна новая загрузка с `--as-of`.

Проверки:

```bash
uv run ruff check
uv run ruff format --check
uv run ty check
uv run pytest
uv run python -m scripts.qualify_stage_c --output artifacts/private/recalc.json
```

Последняя команда проверяет синтетический пересчёт в LibreOffice при его наличии.
Она не заменяет native Microsoft Excel и визуальную приёмку Windows человеком.
Синтетическая демонстрация: `scripts.make_synthetic_demo --output-dir <новый каталог>`;
в ней вымышленные идентификаторы и календарь. Производственные источники, анкеты,
построчные отчёты и журналы остаются локальными и не входят в публичные assets.
