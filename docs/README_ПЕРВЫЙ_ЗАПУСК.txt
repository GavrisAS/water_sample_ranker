Water Sample Ranker
TECHNICAL PREVIEW — НЕ УТВЕРЖДЁННЫЙ РЕЙТИНГ

1. Проверьте SHA-256 скачанного ZIP: в PowerShell выполните
   Get-FileHash .\Water_Sample_Ranker-vVERSION-windows-x64.zip -Algorithm SHA256
   Сравните результат со строкой в соседнем файле .zip.sha256 того же релиза.
   VERSION — номер из имени скачанного файла.
2. Распакуйте ZIP целиком в отдельную папку на локальном диске Windows x64.
   Сохраните рядом с Water_Sample_Ranker.exe папки _internal и templates.
   Python и uv на компьютере пользователя не требуются.
3. Запустите Water_Sample_Ranker.exe. Выберите свои локальные источники и
   отдельное новое имя результата. config.example.toml — безопасный пример;
   пути можно указать в окне приложения.
4. Нажмите «Проверить файлы», выберите месторождение (или все), затем
   «Обновить калькулятор». При необходимости используйте «Отмена».
   Повторный запуск требует нового имени/каталога: результаты не затираются.

Книга содержит листы README / Настройки / Данные / Критерии / Расчет / Рейтинг.
Навигация соответствует образцу ГДИС. Баллы, ранги и TOP не рассчитываются:
методика не утверждена. №7–9 содержат диагностические наблюдения и кандидатов,
которые не подтверждают критерий. UNKNOWN означает недостаточность или
неоднозначность доказательств, а не FALSE и не ноль. Покрытие не является баллом.

Неопределённые истории и конфликты пар ЛХА — отдельные классы диагностики.
Количество зависит от выбранных файлов; приложение сохраняет такие строки.
Для решения нужны актуальные источники и приватная сверка исходных ячеек.
Нельзя переносить контрольные количества одного пакета на другие файлы.
Условная effective_date частичной даты не является точной датой ГТМ;
для cutoff используются полные календарные границы месяца/года.

Версия приложения указана в «О программе» и build-manifest.json.
Используются Qt/PySide6/Shiboken6 (LGPLv3), Python и другие библиотеки;
уведомления и тексты их лицензий находятся в THIRD_PARTY_NOTICES.txt и licenses/.
Для CLI windowed EXE используйте --cli --cli-log <новый_локальный_журнал.log>
перед validate/update/update-all. Журнал создаётся исключительно под новым именем;
он приватный. Консоль не требуется; не размещайте журнал с реальными данными в Issues.
Исторический идентификатор формата шаблона water-v0.2-stage-A и подписи v0.2
относятся к проектной структуре Excel, а не к версии приложения или принятой
методике. Шаблон не подтверждён native Microsoft Excel для этого продукта.
Автоматическая Windows-сборка и Qt smoke не заменяют ручную приёмку интерфейса.
Native Excel / ручная Windows UX / утверждение методики: NOT_RUN / PENDING.

Данные остаются на вашем компьютере. Приложение не загружает промысловые файлы
в GitHub. Соседние .load-report.json и .log содержат приватную диагностику.
Не размещайте реальные книги, номера/координаты, отчёты или анкеты в public
Issues. Передавайте замечания владельцу по уже согласованному приватному каналу.
Для публичного Issue допустимы версия, описание действий и синтетический пример.
Адрес Issues указан на странице репозитория; адреса почты здесь не задаются.

update-all считается завершённым только при успешной проверке bundle-complete.json,
его привязки к источникам/дате/версии и SHA-256 всех обязательных выходов.
Наличие имени маркера само по себе не доказывает COMPLETE. После аварии оставшиеся
файлы не удаляются автоматически: сохраните их и выберите новый каталог.
